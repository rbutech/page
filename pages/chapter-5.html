3. Database fundamentals

Definition: a relational database stores related data in tables. A table has columns (fields) and rows (records). A primary key uniquely identifies each row.

Server → database → table

MySQL Server └── python_school (database) └── students (table) ├── id (primary key) ├── name ├── email └── age

IDs uniquely identify records. Email is also unique in our schema.

Why it matters: constraints such as NOT NULL, UNIQUE and primary keys help the database protect data consistency, even if an application has a bug.

Foreign keys

A foreign key in one table points to a key in another table. For example, an enrollments.student_id column can reference students.id. This helps prevent an enrollment from referring to a student that does not exist.

CREATE TABLE enrollments (
    id INT AUTO_INCREMENT PRIMARY KEY,
    student_id INT NOT NULL,
    course_name VARCHAR(100) NOT NULL,
    CONSTRAINT fk_enrollment_student
      FOREIGN KEY (student_id) REFERENCES students(id)
);

Common mistake: treating an ID as the row number. IDs identify records; gaps can appear after deletions and are normal.

Exercise: design a table for books with an ID, title, author, and publication year. Which field should be the primary key?

4. Install MySQL on Windows

Install a local MySQL Server, configure a strong administrator password, then use a dedicated application user for your Python program. MySQL Workbench is an optional graphical client; the server itself is the database service.

  1. Open the official MySQL installation guide and follow the Windows installer instructions.
  2. Choose MySQL Server and configure it as a Windows service. Keep the server on localhost for local practice.
  3. Set a strong root/admin password and store it securely. Do not use the administrator account in your application.
  4. Open MySQL Workbench or the MySQL command-line client and connect to your local server.
  5. Create the practice database and a dedicated user using the SQL shown below.

Install the Python driver

py -m pip install mysql-connector-python

Verify that Python can import the driver:

py -c "import mysql.connector; print(mysql.connector.__version__)"
Expected output: a version number, for example 9.x.x. The exact version may differ.

Common mistakes: installing the package into a different Python environment, forgetting to start the MySQL service, using the wrong port, or confusing the MySQL server package with the Python connector.

5. Create the database and students table

Run these statements in MySQL Workbench or a MySQL SQL console. SQL is sent to the database server; Python will send similar statements later through the connector.

CREATE DATABASE IF NOT EXISTS python_school;
USE python_school;

CREATE TABLE IF NOT EXISTS students (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    email VARCHAR(150) NOT NULL UNIQUE,
    age INT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

INSERT INTO students (name, email, age)
VALUES
    ('Asha', 'asha@example.com', 20),
    ('Ravi', 'ravi@example.com', 22),
    ('Mina', 'mina@example.com', 19);

SELECT id, name, email, age, created_at
FROM students
ORDER BY id;

6. SQL fundamentals

SQL describes what data operation you want the server to perform. A cursor sends SQL to MySQL and can retrieve the result set or report how many rows were affected.

GoalSQL patternWhat it does
Create schemaCREATE DATABASE ...Creates a database.
Add recordINSERT INTO students (...) VALUES (...)Adds a row.
Read recordsSELECT name, age FROM studentsReturns selected columns.
FilterWHERE age >= 20Keeps rows matching a condition.
SortORDER BY name ASCSorts results alphabetically.
UpdateUPDATE students SET age = 21 WHERE id = 1Changes matching rows.
DeleteDELETE FROM students WHERE id = 1Removes matching rows.

Filtering, sorting and aggregates

SELECT name, age
FROM students
WHERE age >= 20
ORDER BY age DESC;

SELECT COUNT(*) AS student_count,
       AVG(age) AS average_age,
       MIN(age) AS youngest,
       MAX(age) AS oldest
FROM students;

Expected: the first query returns students aged 20 or above, oldest first. The second returns one summary row with count, average, minimum and maximum age. Aggregate functions include COUNT, SUM, AVG, MIN and MAX.

Common mistake: running UPDATE or DELETE without a WHERE clause can affect every row in the table. First test the matching rows with a SELECT query, then run the change deliberately.

7. Python database driver: connection and cursor

Definition: MySQL Connector/Python is a driver that lets Python open a MySQL connection and send SQL. A connection represents a session with the server; a cursor executes statements and reads results.

Set environment variables on Windows PowerShell

$env:DB_HOST = "127.0.0.1"
$env:DB_PORT = "3306"
$env:DB_NAME = "python_school"
$env:DB_USER = "student_app"
$env:DB_PASSWORD = "YOUR_LOCAL_PASSWORD"

These commands set variables for the current PowerShell session. For long-term or production use, use a protected local environment file excluded from version control, the operating system's secret facilities, or a managed secret manager.

Minimal safe connection example

import os
import mysql.connector
from mysql.connector import Error

def get_connection():
    return mysql.connector.connect(
        host=os.getenv("DB_HOST", "127.0.0.1"),
        port=int(os.getenv("DB_PORT", "3306")),
        database=os.getenv("DB_NAME", "python_school"),
        user=os.getenv("DB_USER", "student_app"),
        password=os.getenv("DB_PASSWORD", ""),
        connection_timeout=5,
    )

def main():
    connection = None
    cursor = None
    try:
        connection = get_connection()
        cursor = connection.cursor()
        cursor.execute("SELECT id, name, email, age FROM students ORDER BY id")
        for row in cursor.fetchall():
            print(row)
    except Error:
        # Log a safe message; don't print passwords or connection secrets.
        print("Database operation failed. Check configuration and server status.")
    finally:
        if cursor is not None:
            cursor.close()
        if connection is not None and connection.is_connected():
            connection.close()

if __name__ == "__main__":
    main()
Expected: tuples such as (1, 'Asha', 'asha@example.com', 20), one per saved student. Your IDs and data may differ.
Why use finally?

The finally block runs whether the operation succeeds or raises an exception. It is a useful place to close a cursor and connection. In larger programs, a context manager or a carefully designed repository layer can centralize cleanup.

SQL injection: unsafe versus safe

❌ Unsafe pattern

Do not build a SQL statement by inserting user-provided text into the SQL string.

# Do not do this:
sql = "SELECT * FROM students WHERE name = '" + name + "'"

This mixes query structure with data and can change the meaning of the statement.

✅ Safe pattern

Keep SQL structure fixed and pass values separately using the connector's %s placeholders.

sql = "SELECT id, name FROM students WHERE name = %s"
cursor.execute(sql, (name,))

The comma makes (name,) a one-item tuple. Never use Python string formatting to insert values into SQL.

Rule: use parameterized queries for values in INSERT, SELECT, UPDATE and DELETE. SQL identifiers such as table names cannot generally be passed as ordinary value placeholders; keep identifiers fixed or validate them against a strict allowlist.

10. CREATE: insert a student

Purpose: INSERT adds a new record. MySQL generates the ID because the schema defines AUTO_INCREMENT.

def create_student(name, email, age):
    name = name.strip()
    email = email.strip().lower()
    if not name:
        raise ValueError("Name is required")
    if "@" not in email:
        raise ValueError("Enter a valid email")
    if age is not None and not 1 <= age <= 120:
        raise ValueError("Age must be between 1 and 120")

    connection = get_connection()
    cursor = None
    try:
        cursor = connection.cursor()
        cursor.execute(
            "INSERT INTO students (name, email, age) VALUES (%s, %s, %s)",
            (name, email, age)
        )
        connection.commit()
        return cursor.lastrowid
    except Exception:
        connection.rollback()
        raise
    finally:
        if cursor is not None:
            cursor.close()
        connection.close()

new_id = create_student("Leena", "leena@example.com", 21)
print("Created student ID:", new_id)
Expected: Created student ID: 4 (the actual ID depends on the rows already stored).

Explanation: input validation catches obvious errors before sending data to the database. The SQL placeholders keep user values separate from SQL structure. commit() makes the insert permanent. If an error occurs before commit, rollback() cancels the transaction.

Common mistakes: inserting a duplicate email, omitting the tuple around parameter values, or forgetting to commit. Security: never concatenate a name or email into SQL.

11. UPDATE: modify an existing student

UPDATE changes the columns of rows matching a condition. The ID should be validated, and the WHERE clause should be intentional.

def update_student(student_id, age):
    if not isinstance(student_id, int) or student_id <= 0:
        raise ValueError("Student ID must be a positive integer")
    if not isinstance(age, int) or not 1 <= age <= 120:
        raise ValueError("Age must be between 1 and 120")

    connection = get_connection()
    cursor = None
    try:
        cursor = connection.cursor()
        cursor.execute(
            "UPDATE students SET age = %s WHERE id = %s",
            (age, student_id)
        )
        connection.commit()
        return cursor.rowcount
    except Exception:
        connection.rollback()
        raise
    finally:
        if cursor is not None:
            cursor.close()
        connection.close()

print("Rows matched/changed:", update_student(1, 21))
Expected: Rows matched/changed: 1 when one row is updated. If the ID does not exist, the count is 0. Connector/MySQL settings can affect whether unchanged values count as changed rows.

Common mistake: omitting WHERE id = %s and unintentionally updating every student. Always check the target ID and consider reporting a not-found result when the row count is zero.

Exercise: change the age of student 2 to 23 and verify it with SELECT.

12. DELETE: remove a student

DELETE removes rows. In a real system, deletion may need authorization, confirmation, audit logging or a soft-delete design.

def delete_student(student_id):
    if not isinstance(student_id, int) or student_id <= 0:
        raise ValueError("Student ID must be a positive integer")

    connection = get_connection()
    cursor = None
    try:
        cursor = connection.cursor()
        cursor.execute(
            "DELETE FROM students WHERE id = %s",
            (student_id,)
        )
        connection.commit()
        return cursor.rowcount
    except Exception:
        connection.rollback()
        raise
    finally:
        if cursor is not None:
            cursor.close()
        connection.close()

deleted = delete_student(3)
print("Rows deleted:", deleted)
Expected: Rows deleted: 1 if ID 3 existed; otherwise 0.
Safety habit: before a real DELETE, run a SELECT with the same WHERE condition and verify the target. Never use a broad DELETE statement casually.

Common mistake: confusing deleting a row with dropping a table. DELETE removes matching rows; DROP TABLE removes the table definition and its data.

13. Reusable Student CRUD application

This example is organized into small functions so the terminal interface and a future API can reuse the same database operations. Save as student_app.py. First install the connector and set the environment variables described earlier.

import os
import logging
import mysql.connector
from mysql.connector import Error, IntegrityError

logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s %(levelname)s %(name)s: %(message)s"
)
logger = logging.getLogger("student_app")


def get_connection():
    """Open a short-lived connection using environment configuration."""
    return mysql.connector.connect(
        host=os.getenv("DB_HOST", "127.0.0.1"),
        port=int(os.getenv("DB_PORT", "3306")),
        database=os.getenv("DB_NAME", "python_school"),
        user=os.getenv("DB_USER", "student_app"),
        password=os.getenv("DB_PASSWORD", ""),
        connection_timeout=5,
    )


def _validate_student(name, email, age):
    name = name.strip()
    email = email.strip().lower()
    if not name:
        raise ValueError("Name is required.")
    if "@" not in email or email.startswith("@") or email.endswith("@"):
        raise ValueError("Enter a valid email address.")
    if age is not None and not 1 <= age <= 120:
        raise ValueError("Age must be between 1 and 120.")
    return name, email, age


def create_student(name, email, age):
    name, email, age = _validate_student(name, email, age)
    connection = cursor = None
    try:
        connection = get_connection()
        cursor = connection.cursor()
        cursor.execute(
            "INSERT INTO students (name, email, age) VALUES (%s, %s, %s)",
            (name, email, age)
        )
        connection.commit()
        logger.info("Created student id=%s", cursor.lastrowid)
        return cursor.lastrowid
    except IntegrityError:
        if connection and connection.is_connected():
            connection.rollback()
        logger.warning("Student insert rejected by a database constraint")
        raise ValueError("That email may already be registered.")
    except Error:
        if connection and connection.is_connected():
            connection.rollback()
        logger.exception("Database error while creating student")
        raise
    finally:
        if cursor:
            cursor.close()
        if connection and connection.is_connected():
            connection.close()


def get_students():
    connection = cursor = None

        connection = get_connection()

def read_int(prompt, minimum=1, maximum=120):
    raw = input(prompt).strip()
    try:
        value = int(raw)
    except ValueError:
        raise ValueError("Please enter a whole number.")
    if not minimum <= value <= maximum:
        raise ValueError(f"Enter a number from {minimum} to {maximum}.")
    return value


def main():

        "\\nSTUDENT MANAGEMENT\\n"
        "1. Add student\\n2. List students\\n3. Search by ID\\n"
        "4. Update age\\n5. Delete student\\n0. Exit"
    )
    while True:
        print(menu)
        choice = input("Choose: ").strip()
        try:
            if choice == "1":
                name = input("Name: ")
                email = input("Email: ")
                age = read_int("Age (1-120): ")
                print("Created student ID:", create_student(name, email, age))
            elif choice == "2":
                for student in get_students():
                    print(student)
            elif choice == "3":
                student_id = read_int("Student ID: ", 1, 2_147_483_647)
                print(get_student_by_id(student_id) or "Student not found.")
            elif choice == "4":
                student_id = read_int("Student ID: ", 1, 2_147_483_647)
                age = read_int("New age (1-120): ")
                count = update_student(student_id, age)
                print("Updated." if count else "Student not found or unchanged.")
            elif choice == "5":
                student_id = read_int("Student ID: ", 1, 2_147_483_647)
                confirm = input("Type DELETE to confirm: ")
                if confirm == "DELETE":
                    count = delete_student(student_id)
                    print("Deleted." if count else "Student not found.")
                else:
                    print("Cancelled.")
            elif choice == "0":
                print("Goodbye!")
                break
            else:
                print("Choose one of the listed menu options.")
        except ValueError as exc:
            print("Input:", exc)
        except Error:
            print("Database unavailable or operation failed. Check configuration and logs.")


if __name__ == "__main__":
    main()

14. Transactions, commit and rollback

A transaction groups database changes so they can succeed together or be cancelled together. This matters when a business operation changes multiple related records.

BEGIN TRANSACTION
↓
Operation A
↓
Operation B
↓
Did all operations succeed?
YES → COMMIT

Save all changes.

NO → ROLLBACK

Cancel uncommitted changes.

Choose a scenario and run the safe visual simulation. No database is contacted.

Python transaction pattern

connection = get_connection()
cursor = None
try:
    cursor = connection.cursor()
    cursor.execute(
        "UPDATE students SET age = %s WHERE id = %s",
        (21, 1)
    )
    # Additional related SQL statements could run here.
    connection.commit()
except Exception:
    connection.rollback()
    raise
finally:
    if cursor:
        cursor.close()
    connection.close()

Commit: make the transaction's changes permanent. Rollback: cancel uncommitted changes after failure. A successful SELECT normally does not need a commit. In MySQL, transactional guarantees depend on using a transactional storage engine such as InnoDB.

15. Database security checklist

Access and secrets

  • Use a dedicated application database user.
  • Grant least privilege; avoid root/admin for the app.
  • Use environment variables or a secret manager.
  • Never commit passwords, tokens or private keys.
  • Rotate credentials when exposed.

Queries and operations

  • Use parameterized SQL for all user values.
  • Validate inputs and enforce database constraints.
  • Set connection timeouts and handle errors safely.
  • Log operation context without logging passwords.
  • Back up data and test restoration.

Network and deployment

  • Keep MySQL on a private network or localhost for development.
  • Do not expose MySQL directly to the public internet.
  • Use TLS where connections cross untrusted networks.
  • Restrict firewall rules and database host access.
  • Use pooling carefully in multi-request applications.

Connection pooling concepts

A connection pool maintains a limited set of open connections and lends them to operations as needed. It reduces repeated connection setup overhead and helps cap concurrent connections. Pools must be sized for the server and application, and borrowed connections must be returned reliably. For a small command-line script, opening and closing one connection per operation can be simpler; for a web application, a well-managed pool or framework-supported lifecycle is often appropriate.

Use logger.exception() inside an exception handler when a traceback is useful for operators. Avoid logging credentials, full payment data, or sensitive personal information.

Small FastAPI example

Install FastAPI and an ASGI server with py -m pip install fastapi uvicorn. This example demonstrates validation and calling the reusable functions from a module named student_app.py. It assumes that module contains the CRUD functions from the previous section.

from fastapi import FastAPI, HTTPException, status
from pydantic import BaseModel, Field, EmailStr
from mysql.connector import Error
import student_app

app = FastAPI(title="Student API")

class StudentCreate(BaseModel):
    name: str = Field(min_length=1, max_length=100)
    email: EmailStr
    age: int = Field(ge=1, le=120)

@app.get("/students")
def list_students():
    try:
        return student_app.get_students()
    except Error:
        raise HTTPException(
            status_code=503, detail="Student service temporarily unavailable"
        )

@app.get("/students/{student_id}")
def read_student(student_id: int):
    if student_id <= 0:
        raise HTTPException(status_code=422, detail="ID must be positive")
    try:
        student = student_app.get_student_by_id(student_id)
    except Error:
        raise HTTPException(status_code=503, detail="Database unavailable")
    if student is None:
        raise HTTPException(status_code=404, detail="Student not found")
    return student

@app.post("/students", status_code=status.HTTP_201_CREATED)
def add_student(payload: StudentCreate):
    try:
        student_id = student_app.create_student(
            payload.name, payload.email, payload.age
        )
        return {"id": student_id, "message": "Student created"}
    except ValueError as exc:
        raise HTTPException(status_code=409, detail=str(exc))
    except Error:
        raise HTTPException(status_code=503, detail="Database unavailable")
This is an introductory slice, not the entire production API. Add update and delete endpoints, authentication, authorization, rate limiting, appropriate status codes, tests and a carefully managed connection lifecycle. A synchronous MySQL connector is fine for a beginner synchronous route; do not block async routes with synchronous database calls without considering the execution model.

Run the API

py -m uvicorn api:app --reload

Save the FastAPI code as api.py. Once running locally, the interactive API docs are typically at /docs on the local server. Do not expose a development server or database publicly without appropriate deployment controls.
