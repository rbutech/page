3. Functions

Why functions are needed

A function is a named, reusable block of code that performs a specific task.

Why it matters: Without functions, the same calculation or operation may be copied throughout your program. Functions give you one place to maintain the logic.
Real-world analogy: Think of a coffee machine. You press a button instead of manually performing every step required to make coffee.
calculator.py 
def add(a, b):
    return a + b

result = add(10, 20)
print(result)
30

The def keyword defines the function. The function receives a and b, calculates their sum, and returns the result.

Common mistake: Defining a function does not execute it. You must call it: add(10, 20).
Exercise: Create a subtract(a, b) function that returns the difference.

4. Parameters and Arguments

Parameters describe what a function accepts. Arguments are the actual values you provide when calling the function.

Diagram C — Parameters versus Arguments
Definition 
def greet(name, message="Hello"):
    return f"{message}, {name}!"
name → parameter
message → parameter with a default value
↓
greet("Asha", "Welcome")
"Asha" → positional argument
"Welcome" → positional argument

Positional arguments

Values are assigned according to their position.

positional.py 
def introduce(name, age):
    print(name, age)

introduce("Asha", 21)
Asha 21

Keyword arguments

Keyword arguments explicitly identify the parameter being assigned.

keyword.py 
def introduce(name, age):
    print(name, age)

introduce(age=21, name="Asha")
Asha 21

Default arguments

default.py 
def greet(name, message="Hello"):
    return f"{message}, {name}"

print(greet("Asha"))
print(greet("Ravi", "Welcome"))
Hello, Asha Welcome, Ravi
Analogy: A default argument is like a form field with a pre-filled value. You can accept the default or provide a different value.

*args

Use *args when a function should accept any number of positional arguments.

args.py 
def total(*args):
    return sum(args)

print(total(10, 20))
print(total(1, 2, 3, 4, 5))
30 15

**kwargs

Use **kwargs when a function should accept any number of keyword arguments.

kwargs.py 
def show_profile(**kwargs):
    for key, value in kwargs.items():
        print(key, "=", value)

show_profile(
    name="Asha",
    age=21,
    course="Python"
)
name = Asha age = 21 course = Python
Common mistake: Do not confuse *args with a list. Inside the function, args is a tuple.
Exercise: Create a function called average(*numbers) that returns the average of all supplied numbers.

5. Return Values

The return statement sends a value back to the code that called the function.

multiple_values.py 
def calculate(a, b):
    total = a + b
    difference = a - b
    product = a * b

    return total, difference, product

result = calculate(20, 5)

print(result)
print(result[0])
print(result[1])
print(result[2])
(25, 15, 100) 25 15 100

Python can return multiple values. Technically, Python packages them into a tuple.

Analogy: A restaurant can return an entire meal containing several items instead of returning only one item.
Exercise: Create a function that receives a student's marks and returns: total, average, and highest mark.

7. Lambda and Functional Tools

Lambda functions

A lambda is a small anonymous function. It is useful when a short function is needed only once or as an argument to another function.

lambda.py 
square = lambda x: x * x

print(square(5))
25

map()

map() applies a function to every item in an iterable.

map.py 
numbers = [1, 2, 3, 4, 5]

squares = list(map(lambda x: x * x, numbers))

print(squares)
[1, 4, 9, 16, 25]

filter()

filter() keeps items for which a function returns True.

filter.py 
numbers = [1, 2, 3, 4, 5, 6]

even_numbers = list(
    filter(lambda x: x % 2 == 0, numbers)
)

print(even_numbers)
[2, 4, 6]
Use lambda when: The operation is tiny and simple.
Use map when: Every item needs to be transformed.
Use filter when: You need to select matching items.
Prefer normal def when: The logic is complex or reused.
Exercise: Use filter() to keep only students whose marks are at least 50.

10. Class Attributes, Class Methods and Static Methods

Class attributes

A class attribute is shared by objects of the class.

class_attribute.py 
class Student:

    school = "RBUtech"

    def __init__(self, name):
        self.name = name

a = Student("Asha")
b = Student("Ravi")

print(a.school)
print(b.school)
RBUtech RBUtech

Class methods

A class method receives the class itself as cls.

classmethod.py 
class Student:

    school = "RBUtech"

    @classmethod
    def school_name(cls):
        return cls.school

print(Student.school_name())
RBUtech

Static methods

A static method does not require either an instance or class reference. It is useful for helper logic related conceptually to the class.

staticmethod.py 
class Student:

    @staticmethod
    def is_valid_mark(mark):
        return 0 <= mark <= 100

print(Student.is_valid_mark(90))
print(Student.is_valid_mark(120))
True False
Feature Receives Use when
Instance method self Working with an object's data
Class method cls Working with class-level state or alternate constructors
Static method Nothing automatically Utility logic related to the class

11. Encapsulation

Encapsulation means controlling how an object's internal state is accessed or changed.

Diagram H — Encapsulation
Application
↓
Public method: deposit()
↓
Object validation
↓
Internal state update
Analogy: An ATM does not let you directly modify the bank's database. You interact through controlled operations such as deposit and withdrawal.
bank_account.py 
class BankAccount:

    def __init__(self, balance=0):
        self._balance = balance

    def deposit(self, amount):
        if amount <= 0:
            raise ValueError("Amount must be positive")

        self._balance += amount

    def withdraw(self, amount):
        if amount > self._balance:
            raise ValueError("Insufficient funds")

        self._balance -= amount

    def get_balance(self):
        return self._balance


account = BankAccount(100)

account.deposit(50)
account.withdraw(30)

print(account.get_balance())
120
Important: Python does not enforce private fields in the same way as some languages. A leading underscore is primarily a convention meaning "internal use".
Exercise: Add a withdraw() validation rule that rejects negative or zero withdrawal amounts.

12. Inheritance

Inheritance allows a child class to reuse behavior from a parent class.

Diagram G — Inheritance
Person
↓
Student
Employee
inheritance.py 
class Person:

    def __init__(self, name):
        self.name = name

    def introduce(self):
        print(f"My name is {self.name}")


class Employee(Person):

    def work(self):
        print(f"{self.name} is working")


employee = Employee("Ravi")

employee.introduce()
employee.work()
My name is Ravi Ravi is working

The Employee class inherited __init__() and introduce() from Person, while adding its own work() method.

Method overriding

A child class can replace inherited behavior by defining a method with the same name.

override.py 
class Person:

    def introduce(self):
        print("I am a person")


class Student(Person):

    def introduce(self):
        print("I am a student")


person = Person()
student = Student()

person.introduce()
student.introduce()
I am a person I am a student

13. Polymorphism

Polymorphism means that different objects can respond to the same operation in their own way.

Diagram I — Polymorphism and Duck Typing
Dog

speak()

→ Woof

Cat

speak()

→ Meow

Same interface

animal.speak()

polymorphism.py 
class Dog:

    def speak(self):
        return "Woof"


class Cat:

    def speak(self):
        return "Meow"


def make_speak(animal):
    print(animal.speak())


dog = Dog()
cat = Cat()

make_speak(dog)
make_speak(cat)
Woof Meow
Duck typing: Python generally cares about what an object can do rather than what class it belongs to. If an object provides the required speak() behavior, the function can use it.
Analogy: If you ask two people to "speak", you don't care about their job title. You care that they can perform the requested action.

Composition means building an object by combining other objects. It represents a has-a relationship.

composition.py 
class Engine:

    def start(self):
        return "Engine started"


class Wheels:

    def rotate(self):
        return "Wheels rotating"


class Battery:

    def power(self):
        return "Battery supplying power"


class Car:

    def __init__(self):
        self.engine = Engine()
        self.wheels = Wheels()
        self.battery = Battery()

    def drive(self):
        print(self.battery.power())
        print(self.engine.start())
        print(self.wheels.rotate())


car = Car()
car.drive()
Battery supplying power Engine started Wheels rotating
Relationship Meaning Example

has-a Composition Car has an Engine

18. Practical Project — Student Management Program

This project combines classes, constructors, instance attributes, methods, validation, lists, input handling and grade calculation.

Project requirements

Add student Store a student's name and marks.
Average Calculate average marks.
Grade Convert average into a grade.
Validation Only accept marks from 0 to 100.
Display Show complete student information.
Error handling Handle invalid terminal input.

Complete runnable program

student_management.py 
class Student:

    def __init__(self, name, marks):
        self.name = name
        self.marks = marks

    def average(self):
        if not self.marks:
            return 0

        return sum(self.marks) / len(self.marks)

    def grade(self):
        avg = self.average()

        if avg >= 90:
            return "A"
        elif avg >= 80:
            return "B"
        elif avg >= 70:
            return "C"
        elif avg >= 60:
            return "D"
        else:
            return "F"

    def display(self):
        print("\nStudent:", self.name)
        print("Marks:", self.marks)
        print("Average:", round(self.average(), 2))
        print("Grade:", self.grade())


def read_mark(subject):
    while True:
        try:
            mark = float(
                input(f"Enter marks for {subject}: ")
            )

            if 0 <= mark <= 100:
                return mark

            print("Marks must be between 0 and 100.")

        except ValueError:
            print("Please enter a valid number.")


students = []

while True:

    print("\n--- Student Management ---")
    print("1. Add student")
    print("2. Display students")
    print("3. Exit")

    choice = input("Choose an option: ")

    if choice == "1":

        name = input("Enter student name: ")

        subjects = ["Python", "Math", "English"]
        marks = []

        for subject in subjects:
            marks.append(read_mark(subject))

        student = Student(name, marks)
        students.append(student)

        print("Student added successfully.")

    elif choice == "2":

        if not students:
            print("No students available.")
        else:
            for student in students:
                student.display()

    elif choice == "3":

        print("Goodbye!")
        break

    else:
        print("Invalid choice.")

How the project works

1. Student class
The class stores the student's name and marks and provides behavior for calculating averages, grades, and displaying information.
2. Constructor
__init__() initializes the student's name and marks.
3. average()
The method uses sum() and len() to calculate the average.
4. grade()
Conditional logic converts the average into a letter grade.
5. read_mark()
A loop repeatedly asks for input until the user provides a valid number between 0 and 100.
6. Main program
The program stores Student objects in a list and allows the user to add, display, or exit.

21. Summary

Functions Package reusable behavior into named blocks.
Parameters Define what a function can receive.
Return Send calculated values back to the caller.
Scope Controls where variables are accessible.
Classes Define reusable object blueprints.
Objects Store individual instance data.
Inheritance Reuse and specialize parent behavior.
Polymorphism Allow different objects to share an interface.
Composition Build complex objects from smaller objects.

When should you use each concept?

Concept Use it when...
Function You have reusable behavior or a task that deserves a name.
Parameters The behavior needs input.
Return The caller needs a result.
*args The number of positional inputs can vary.
**kwargs The number of named inputs can vary.
Lambda A tiny one-expression function is sufficient.
Class Data and behavior naturally belong together.
Inheritance There is a genuine "is-a" relationship and useful shared behavior.
Encapsulation State needs controlled access or validation.
Polymorphism Different objects should support the same operation.
Composition A larger object is built from smaller cooperating objects.
Architect's rule: Do not use classes simply because Python supports classes. Start with simple functions and data structures. Introduce classes when your program contains objects with meaningful state, behavior, and relationships.
