2. Python Modules

What is a module?

A module is a Python file containing reusable code, such as functions, variables and classes. A file named helpers.py is a module named helpers.

Without modules

Every file repeats the same validation, calculation and formatting logic.

With modules

Write reusable logic once and import it wherever it is needed.

Diagram C: Module Import Flow

main.py
Application entry point
→
import helpers
→
helpers.py
Reusable functions
→
Results returned to main.py

2.1 Importing built-in modules

Python includes many modules. The math module provides mathematical functions, while datetime provides date and time functionality.

import math
import datetime

print(math.sqrt(81))
print(math.ceil(4.2))
print(datetime.date(2026, 10, 27))
Expected output: 9.0 5 2026-10-27

Common import styles

import math
print(math.pi)

from math import sqrt
print(sqrt(49))

import datetime as dt
print(dt.date.today())

Explanation: import math imports the module. from math import sqrt imports one named item. as dt creates an alias.

Expected output: The first two calls print pi and 7.0. The final call prints today's date when you run the program.

Common mistakes:
  • Using Math instead of math. Python names are case-sensitive.
  • Naming your own file math.py, json.py or datetime.py, which can shadow a standard-library module.
  • Importing a module that has not been installed or is not available in your Python environment.

2.2 Creating a custom module

Create two files in the same directory: helpers.py and main.py.

# helpers.py

def greet(name):
    return f"Hello, {name}!"

def add(a, b):
    return a + b
# main.py

import helpers

print(helpers.greet("Naveen"))
print(helpers.add(10, 20))
Expected output: Hello, Naveen! 30

How it works: Python locates helpers.py on its import search path, loads the module and makes its functions available through helpers.

Real-world use: Put common validation, date formatting, calculations or API helpers into separate modules.

Expand: Why use if __name__ == "__main__"?

This guard runs code only when the file is executed directly, not when it is imported as a module.

def greet():
    print("Hello from helpers")

if __name__ == "__main__":
    greet()

Use it for simple demonstrations, command-line entry points and local testing.

3. Python Packages

A package groups related Python modules into a directory. This helps organize larger applications by feature or responsibility.

shop_app/ ├── main.py └── services/ ├── __init__.py ├── billing.py └── notifications.py

Creating a package

Create a directory named services, then add the following files.

# services/__init__.py
# This file marks services as a regular package.
# It may also expose selected package functions.
# services/billing.py

def calculate_total(price, quantity):
    return price * quantity
# main.py

from services.billing import calculate_total

print(calculate_total(25, 4))
Expected output: 100

Definition: A package is a way to organize related modules. A package can contain subpackages and more modules.

Real-world use: Organize a backend into users, payments, reports and notifications.

Common mistake: Importing with the wrong path or running a file from a directory where Python cannot locate the package.

Modern Python supports namespace packages without __init__.py, but including it is a clear and beginner-friendly choice for a conventional package.

5. Python Virtual Environments

A virtual environment is an isolated Python environment for a project. It allows that project to use its own installed packages.

Why it matters: Project A may need one library version while Project B needs another. Separate environments help prevent dependency conflicts.

Create and activate a virtual environment on Windows

# Run inside your project directory
py -m venv .venv

# Command Prompt
.venv\Scripts\activate.bat

# PowerShell
.\.venv\Scripts\Activate.ps1

# Check which Python is active
python --version

python3 -m venv .venv
source .venv/bin/activate
python --version

Expected result: The environment is created in the .venv directory. After activation, your shell usually shows (.venv) in its prompt.

Common mistakes:
  • Installing packages into a different Python installation from the one running the project.
  • Forgetting to activate the environment.
  • Committing the entire .venv directory to Git. Usually, it should be ignored.

Real-world use: Create a separate environment for each application or project.

6. pip and requirements.txt

pip is Python's commonly used package installer. It installs packages from configured package indexes and other supported sources.

Install and inspect packages

python -m pip --version
python -m pip install requests
python -m pip show requests
python -m pip list

Expected result: pip reports its version, installs the requested package when available, and displays package information.

Save dependencies

# Save installed environment packages
python -m pip freeze > requirements.txt

# Install listed packages in another activated environment
python -m pip install -r requirements.txt

Example requirements.txt:

requests==2.32.3

The version above is an illustrative example, not a guarantee that it is the latest release. Use versions appropriate for your project and test them.

Important distinction: The Python standard library includes modules such as math, json, csv and logging. You do not install these separately with pip.

Real-world use: Developers use dependency files to help reproduce application environments during development, testing and deployment.

Common mistake: Running pip install against the wrong interpreter. Prefer python -m pip after activating the intended environment.

7.5 Why use with open()?

The with statement uses a context manager. When the block ends, Python closes the file even if an exception occurs during the block.

# Recommended
with open("notes.txt", "r", encoding="utf-8") as file:
    content = file.read()

# Manual closing is easier to get wrong
file = open("notes.txt", "r", encoding="utf-8")
try:
    content = file.read()
finally:
    file.close()

7.6 Working with file paths

Use pathlib to represent and work with paths in a readable, cross-platform way.

from pathlib import Path

data_dir = Path("data")
data_dir.mkdir(parents=True, exist_ok=True)

file_path = data_dir / "notes.txt"
file_path.write_text("Hello from pathlib", encoding="utf-8")

print(file_path.exists())
print(file_path.read_text(encoding="utf-8"))
Expected output: True Hello from pathlib
Common mistakes:
  • Using w when you meant a, thereby losing existing content.
  • Forgetting encoding="utf-8" for text files.
  • Assuming a relative path is always relative to the Python file. It is normally resolved from the current working directory.
  • Using r for a missing file without handling the resulting error.

Real-world use: Read reports, save generated files, process uploaded documents and maintain small local datasets.

8. JSON

Definition: JSON (JavaScript Object Notation) is a text format commonly used to exchange structured data between applications and APIs.

Diagram G: JSON structure

{
    "name": "Anita",
    "age": 21,
    "skills": ["Python", "SQL"],
    "active": true
}

Object

{} contains key-value pairs, such as "name": "Anita".

Array

[] contains an ordered list of values, such as the skills list.

String and number

"Anita" is a string; 21 is a number.

Boolean and null

JSON uses true, false and null. In Python, they correspond to True, False and None.

8.1 Write JSON to a file

import json

student = {
    "name": "Anita",
    "age": 21,
    "skills": ["Python", "SQL"],
    "active": True
}

with open("student.json", "w", encoding="utf-8") as file:
    json.dump(student, file, indent=4)

print("JSON saved")
Expected output: JSON saved

8.2 Read JSON from a file

import json

with open("student.json", "r", encoding="utf-8") as file:
    student = json.load(file)

print(student["name"])
print(student["skills"])
Expected output: Anita ['Python', 'SQL']

8.3 Convert between Python and JSON strings

import json

student = {"name": "Ravi", "age": 20}

json_text = json.dumps(student)
print(json_text)

python_data = json.loads(json_text)
print(python_data["name"])
Expected output: {"name": "Ravi", "age": 20} Ravi

Important difference: dump() writes JSON to a file-like object; dumps() returns a JSON string. load() reads from a file-like object; loads() parses a JSON string.

Interactive JSON viewer

Paste JSON into the editor or use the sample. This tool parses and formats JSON locally in the browser.

Formatted JSON appears here.
Common mistakes:
  • Using single quotes around JSON keys or strings. Standard JSON requires double quotes.
  • Writing True or None in JSON. JSON requires true or null.
  • Assuming all Python objects can be serialized automatically. Some types, such as ordinary date objects, need conversion.
  • Trusting malformed or untrusted data without validation.

Real-world use: API requests and responses, application configuration and small structured data files.

9. CSV

Definition: CSV (Comma-Separated Values) is a text format for tabular data. It is commonly used for spreadsheets, reports and data imports.

Example CSV file

name,age,course
Anita,21,Python
Ravi,20,Java

9.1 Writing CSV with DictWriter

import csv

students = [
    {"name": "Anita", "age": 21, "course": "Python"},
    {"name": "Ravi", "age": 20, "course": "Java"}
]

with open("students.csv", "w", newline="", encoding="utf-8") as file:
    fields = ["name", "age", "course"]
    writer = csv.DictWriter(file, fieldnames=fields)
    writer.writeheader()
    writer.writerows(students)

print("CSV saved")
Expected output: CSV saved

9.2 Reading CSV with DictReader

import csv

with open("students.csv", "r", newline="", encoding="utf-8") as file:
    reader = csv.DictReader(file)
    for row in reader:
        print(row["name"], row["course"])
Expected output: Anita Python Ravi Java

Why newline=""? It is the recommended way to open CSV files for reading or writing with Python's csv module, helping avoid extra blank lines on some platforms.

10. Exception Handling

Definition: An exception is an event that interrupts normal program execution. Exception handling lets you respond to expected errors instead of allowing the program to fail unexpectedly.

Diagram H: Exception handling flowchart

The diagram simplifies the flow. If an exception occurs and no handler matches, the exception propagates. A finally block normally runs whether the operation succeeds or fails.

10.1 try and except

try:
    number = int("abc")
    print(number)
except ValueError:
    print("Please provide a valid integer")
Expected output: Please provide a valid integer

Explanation: int("abc") raises ValueError. The matching except block handles it.

10.2 Catching FileNotFoundError

try:
    with open("missing.txt", "r", encoding="utf-8") as file:
        content = file.read()
    print(content)
except FileNotFoundError:
    print("The requested file was not found")
If missing.txt does not exist: The requested file was not found

10.3 Using else and finally

try:
    number = int("25")
except ValueError:
    print("Invalid number")
else:
    print("Conversion successful:", number)
finally:
    print("Conversion attempt finished")
Expected output: Conversion successful: 25 Conversion attempt finished
  • try: contains code that may raise an exception.
  • except: handles a matching exception.
  • else: runs when the try block completes without an exception.
  • finally: normally runs whether an exception occurs or not.

10.4 Interactive exception-flow simulator

Choose a predefined scenario to observe which handler runs. This simulator does not execute Python code.

Common mistakes:
  • Using an empty except: that catches too broadly and hides unexpected problems.
  • Putting success logic in finally rather than else.
  • Displaying an error message but continuing with invalid or incomplete data.
  • Using exceptions for ordinary control flow when a simple condition would be clearer.

Real-world use: Handle invalid input, unavailable files, failed network requests and unexpected data formats.

Exercise: Ask for a number, catch ValueError, and display a friendly message when the user enters text instead of an integer.

11. Raising Exceptions and Custom Exceptions

Use raise when your code detects a situation that should be reported as an error. A custom exception gives your application a meaningful error type.

11.1 Using raise

def calculate_discount(price):
    if price < 0:
        raise ValueError("Price cannot be negative")
    return price * 0.10

print(calculate_discount(100))
Expected output: 10.0

If you call calculate_discount(-10), the function raises a ValueError with the message Price cannot be negative.

11.2 Create a custom exception

class InvalidAgeError(Exception):
    """Raised when an age is outside the allowed range."""


def register_student(name, age):
    if age < 5 or age > 100:
        raise InvalidAgeError("Age must be between 5 and 100")
    return f"Registered: {name}"


try:
    print(register_student("Anita", 21))
    print(register_student("Ravi", 2))
except InvalidAgeError as error:
    print("Registration failed:", error)
Expected output: Registered: Anita Registration failed: Age must be between 5 and 100

Explanation: InvalidAgeError inherits from Exception. The application can catch this specific error separately from unrelated errors.

Best practice: Validate values close to where their rules are known. Use built-in exceptions such as ValueError for standard situations and custom exceptions when application-specific meaning is helpful.

Real-world use: Invalid orders, insufficient account balance, duplicate registrations or application-specific validation failures.

Common mistake: Catching a custom exception too early and silently ignoring the failure.

Exercise: Create InsufficientBalanceError. Raise it when a withdrawal is greater than the available balance.

12. Logging

Definition: Logging records events that happen while an application runs. Logs help developers investigate failures and understand application behavior.

Diagram I: Logging levels

DEBUG Detailed diagnostic information useful during development.
INFO Normal events, such as an application starting or a record being saved.
WARNING Something unexpected happened, but the application can continue.
ERROR An operation failed and requires attention.
CRITICAL A serious failure may prevent the application from continuing normally.

Configure logging

import logging

logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s %(levelname)s %(message)s"
)

logging.debug("Detailed diagnostic information")
logging.info("Student application started")
logging.warning("Student file is empty")
logging.error("Unable to process student record")
logging.critical("Application cannot continue")
Typical output (timestamps vary): 2026-10-27 10:00:00,000 INFO Student application started 2026-10-27 10:00:00,001 WARNING Student file is empty 2026-10-27 10:00:00,002 ERROR Unable to process student record 2026-10-27 10:00:00,003 CRITICAL Application cannot continue

INFO is the configured threshold, so DEBUG is not displayed. The example timestamps are illustrative.

Log an exception

import logging

logging.basicConfig(level=logging.INFO)

try:
    number = int("abc")
except ValueError:
    logging.exception("Could not convert input to an integer")

logging.exception() is intended for use inside an exception handler and includes exception information in the log.

Security warning: Do not log passwords, API keys, access tokens, session cookies or unnecessary personal information. Logs may be stored and accessed by other systems.

Real-world use: Diagnose production failures, monitor scheduled jobs and trace important business operations.

Common mistake: Using print() for every diagnostic event in a production application instead of structured logging.

import os

port_text = os.getenv("APP_PORT", "8000")

try:
    port = int(port_text)
except ValueError as error:
    raise ValueError("APP_PORT must be an integer") from error

if not 1 <= port <= 65535:
    raise ValueError("APP_PORT must be between 1 and 65535")

DATABASE_URL=replace_with_your_database_url

This is documentation for the required configuration keys. The values are placeholders, not real credentials.

Important security rules:
  • Never commit actual passwords, tokens, API keys or production connection strings to Git.
  • Keep any real local .env file out of source control.
  • Use your deployment platform's secret manager or protected environment settings in production.
  • Validate configuration values before opening connections.
  • Do not assume an environment variable is secure simply because it is not hard-coded.

What about .env files?

Python's standard library does not automatically load a .env file. A third-party package, commonly python-dotenv, can load one during development.

Real-world use: Separate development, testing and production settings without changing source code.

Common mistake: Assuming that putting a password in a configuration file automatically protects it. Protection depends on access controls, storage and deployment practices.

14. Practical Project — File-Based Student Records

Build a terminal application that can add students, save records to JSON, display records, search by name, handle missing or malformed files, validate input and log important operations.

Project requirements

Student fields

  • Student ID
  • Name
  • Age
  • Course

Application operations

  • Add a student
  • List saved students
  • Search by name
  • Validate input and handle errors

14.1 Complete working Python program

Save the following as main.py. It uses only Python's standard library.

import json
import logging
from pathlib import Path


DATA_DIR = Path("data")
DATA_FILE = DATA_DIR / "students.json"

logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s %(levelname)s %(message)s"
)


class StudentDataError(Exception):
    """Raised when student data cannot be processed safely."""


def load_students():
    """Load student records from JSON."""
    if not DATA_FILE.exists():
        logging.info("Student file does not exist yet")
        return []

    try:
        with DATA_FILE.open("r", encoding="utf-8") as file:
            students = json.load(file)
    except json.JSONDecodeError as error:
        logging.error("Student JSON is malformed")
        raise StudentDataError(
            "Student data is invalid JSON. Back up the file before repairing it."
        ) from error
    except OSError as error:
        logging.error("Unable to read student file")
        raise StudentDataError("Unable to read student data.") from error

    if not isinstance(students, list):
        raise StudentDataError("Student data must be a JSON list.")

    for student in students:
        if not isinstance(student, dict):
            raise StudentDataError("Every student record must be an object.")

        required = {"id", "name", "age", "course"}
        if not required.issubset(student):
            raise StudentDataError("A student record is missing required fields.")

        if not isinstance(student["name"], str):
            raise StudentDataError("Student names must be strings.")

        if not isinstance(student["age"], int) or isinstance(student["age"], bool):
            raise StudentDataError("Student ages must be integers.")

    return students


def save_students(students):
    """Save student records to JSON."""
    DATA_DIR.mkdir(parents=True, exist_ok=True)

    # Write to a temporary file before replacing the main file.
    temporary_file = DATA_FILE.with_suffix(".tmp")

    try:
        with temporary_file.open("w", encoding="utf-8") as file:
            json.dump(students, file, indent=4, ensure_ascii=False)
            file.write("\n")

        temporary_file.replace(DATA_FILE)
    except OSError as error:
        logging.error("Unable to save student records")
        raise StudentDataError("Unable to save student data.") from error

    logging.info("Saved %d student record(s)", len(students))


def add_student():
    """Collect and validate student details."""
    students = load_students()

    student_id = input("Student ID: ").strip()
    name = input("Student name: ").strip()
    age_text = input("Age: ").strip()
    course = input("Course: ").strip()

    if not student_id or not name or not course:
        print("ID, name and course are required.")
        return

    if any(str(item.get("id", "")).casefold() == student_id.casefold()
           for item in students):
        print("That student ID already exists.")
        return

    try:
        age = int(age_text)
    except ValueError:
        print("Age must be a whole number.")
        return

    if not 5 <= age <= 100:
        print("Age must be between 5 and 100.")
        return

    student = {
        "id": student_id,
        "name": name,
        "age": age,
        "course": course
    }

    students.append(student)
    save_students(students)
    print("Student added successfully.")


def list_students():
    """Display saved student records."""
    students = load_students()

    if not students:
        print("No student records found.")
        return

    for student in students:
        print(
            f"ID: {student['id']} | "
            f"Name: {student['name']} | "
            f"Age: {student['age']} | "
            f"Course: {student['course']}"
        )


def search_students():
    """Search for students by a partial name."""
    query = input("Enter a name to search: ").strip().casefold()

    if not query:
        print("Enter a search name.")
        return

    students = load_students()
    matches = [
        student for student in students
        if query in student["name"].casefold()
    ]

    if not matches:
        print("No matching students found.")
        return

    for student in matches:
        print(
            f"ID: {student['id']} | "
            f"Name: {student['name']} | "
            f"Age: {student['age']} | "
            f"Course: {student['course']}"
        )


def main():
    while True:
        print("\\n--- Student Records ---")
        print("1. Add student")
        print("2. List students")
        print("3. Search by name")
        print("4. Exit")

        choice = input("Choose an option: ").strip()

        try:
            if choice == "1":
                add_student()
            elif choice == "2":
                list_students()
            elif choice == "3":
                search_students()
            elif choice == "4":
                print("Goodbye!")
                break
            else:
                print("Choose 1, 2, 3 or 4.")
        except StudentDataError as error:
            logging.exception("Student operation failed")
            print("Error:", error)


if __name__ == "__main__":
    main()

14.4 Important implementation details

  • Missing file: The application treats a missing student file as an empty list.
  • Malformed JSON: It reports an application error rather than silently replacing the existing data.
  • Validation: It checks required fields, age format, age range and duplicate student IDs.
  • Logging: Important save and error events are recorded.
  • Safer saving: It writes to a temporary file before replacing the data file. This reduces some risks of partial writes but is not a complete transactional or concurrency solution.
Important: Back up students.json before manual repairs. This beginner project is not a production-grade database. Concurrent writers, crashes and storage failures require additional design and testing.

14.5 File-based storage vs database storage

FeatureJSON fileDatabase
SetupVery simpleRequires database setup or a database engine
Best suited forSmall, simple datasets and demonstrationsApplications requiring structured queries and stronger data management
SearchingOften load records and search in application codeCan query indexed data efficiently
Concurrent updatesNeed careful coordination and locking strategiesDatabase transactions and concurrency controls are available
RelationshipsMust be managed by application codeRelational databases can enforce relationships and constraints
GrowthCan become slow or difficult to maintain as data growsUsually better suited to growing business datasets

Real-world use: A JSON file is useful for a learning project or small local utility. For a multi-user school management system, a database such as SQLite, PostgreSQL or MySQL is generally more appropriate.

Extension exercise: Add an update operation, a delete operation and automated tests. Later, replace the JSON repository with a database repository without changing the application's menu logic.
