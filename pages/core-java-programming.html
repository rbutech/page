Core Java Programming — Complete Learning Guide

Core Java is the foundation of enterprise Java development. Before learning Spring Boot, Microservices, Hibernate or cloud-based Java applications, developers must understand the Java language, object-oriented programming, collections, exception handling, memory management and JVM internals.

72 roadmap topics Java fundamentals Code examples Senior developer focus

Learning Objectives

After completing this chapter, you should be able to:

  • Understand how Java source code is compiled and executed.
  • Use Java data types, variables, operators and control statements.
  • Design classes using encapsulation, inheritance and polymorphism.
  • Work with strings, arrays, methods, interfaces and exceptions.
  • Read and write files using Java I/O and NIO APIs.
  • Understand JVM memory areas, garbage collection and class loading.
  • Write maintainable Java code suitable for enterprise applications.

1. Java Foundations

Topic 01

1. Java Introduction and Evolution

Java is a general-purpose, class-based programming language designed to support portability, reliability and object-oriented application development.

Java source code is compiled into bytecode. The Java Virtual Machine (JVM) executes that bytecode on supported platforms. This architecture allows the same compiled application to run on different operating systems when compatible Java runtimes are available.

Java is widely used in enterprise applications, banking systems, telecom platforms, e-commerce, cloud services, Android-related development and distributed systems.

Important: Java is not only a programming language. Its ecosystem includes the JVM, standard libraries, development tools, frameworks and runtime technologies.

Practical example: A telecom billing platform can use Java services to process customer subscriptions, payments, usage records and account updates.

Topic 02

2. JDK, JRE and JVM Architecture

These three terms represent different parts of the Java execution environment.

JDK — Java Development Kit

Provides development tools such as the Java compiler, launcher, debugger and other utilities, along with the runtime components.

JRE — Java Runtime Environment

Traditionally refers to the runtime components and libraries required to run Java applications. Modern JDK distributions may not provide a separate JRE installation.

JVM — Java Virtual Machine

Loads, verifies and executes Java bytecode. It manages runtime memory, garbage collection and execution.

Java Class Libraries

Provide reusable functionality such as collections, I/O, networking, dates, concurrency and utilities.

Remember: JDK is for development; the JVM is the engine that executes bytecode.
Topic 03

3. Java Installation and Environment Setup

Install a supported JDK distribution and configure your development environment. Common distributions include Eclipse Temurin, Oracle JDK and other OpenJDK-based builds.

Important setup components:

  • Install the JDK.
  • Configure JAVA_HOME to point to the JDK installation directory.
  • Add the JDK bin directory to the system PATH.
  • Install an IDE such as IntelliJ IDEA, Eclipse or Spring Tool Suite.
  • Configure Maven or Gradle for project builds.
java -version
javac -version
echo %JAVA_HOME%

On Windows, the environment variable can be configured through System Properties. On Linux, it is commonly configured in shell profile files.

Use the same JDK version in your IDE, terminal and build pipeline to avoid version-related compilation problems.
Topic 04

4. Java Compilation and Execution Process

Java applications normally pass through these stages:

  1. Write source code in a .java file.
  2. Compile source code using javac.
  3. The compiler generates bytecode in a .class file.
  4. The class loader loads required classes.
  5. The JVM verifies and executes bytecode.
// HelloWorld.java
public class HelloWorld {
    public static void main(String[] args) {
        System.out.println("Hello Java");
    }
}

// Compile
javac HelloWorld.java

// Execute
java HelloWorld

The JVM may interpret bytecode and use Just-In-Time (JIT) compilation to compile frequently executed code into native machine code.

Topic 05

5. Java Features and Platform Independence

Java provides several characteristics that make it suitable for large applications:

  • Platform independence: Bytecode can run on compatible JVM implementations.
  • Object-oriented: Supports classes, objects, inheritance and polymorphism.
  • Strongly typed: Variables and expressions have defined types.
  • Automatic memory management: Garbage collection manages many object-lifetime concerns.
  • Multithreading: Provides APIs for concurrent execution.
  • Rich libraries: Includes networking, collections, I/O, security and concurrency APIs.
  • JIT optimization: The runtime can optimize frequently executed code.

Interview concept: Java is often described as platform-independent because the compiler produces bytecode for the JVM rather than directly producing a different executable for every operating system.

2. Data Types, Variables and Operators

Topic 06

6. Java Data Types and Variables

A variable is a named storage location used by a program. Every variable has a type that determines the values it can hold and the operations that can be performed on it.

int employeeId = 101;
String employeeName = "Ravi";
double salary = 19000.50;
boolean active = true;

Java variables can be local variables, instance variables or static variables. Their scope and lifetime depend on where they are declared.

Topic 07

7. Primitive and Non-Primitive Data Types

Java has eight primitive data types:

TypeTypical use
byteSmall integer values
shortShort integer values
intCommon integer values
longLarge integer values
floatSingle-precision decimal values
doubleDouble-precision decimal values
charSingle UTF-16 code unit
booleanTrue or false

Reference types include classes, interfaces, arrays, enums and records. A reference variable refers to an object; it does not directly contain the entire object.

Use BigDecimal rather than float or double when exact decimal arithmetic is required, such as financial calculations.
Topic 08

8. Type Casting and Type Conversion

Type conversion changes a value from one data type to another.

Widening: Converting a smaller compatible numeric type into a wider type. This is generally performed automatically.

Narrowing: Converting a wider type into a smaller type. It requires an explicit cast and may lose information.

int count = 100;
long total = count;       // Widening

double price = 99.75;
int roundedDown = (int) price; // Narrowing: 99

Also understand parsing text into values using methods such as Integer.parseInt() and Double.parseDouble().

Topic 09

9. Operators and Expressions

Operators perform calculations, comparisons and logical operations.

  • Arithmetic: +, -, *, /, %
  • Relational: ==, !=, greater than, less than
  • Logical: &&, ||, !
  • Assignment: =, +=, -=, *=
  • Unary: ++, --, +, -, !
  • Bitwise: &, |, ^, ~
  • Shift: <<, >>, >>>
  • Conditional: condition ? value1 : value2
  • Type comparison: instanceof
int age = 25;
boolean eligible = age >= 18 && age <= 60;

int result = eligible ? 1 : 0;

Understand operator precedence and use parentheses when an expression could be confusing.

3. Control Flow and Arrays

Topic 10

10. Conditional Statements

Conditional statements allow a program to execute different blocks depending on conditions.

int marks = 82;

if (marks >= 90) {
    System.out.println("Excellent");
} else if (marks >= 75) {
    System.out.println("Good");
} else {
    System.out.println("Needs improvement");
}

Learn if, if-else, else-if ladder and switch statements. Modern Java also supports switch expressions.

Topic 11

11. Loops – for, while, do-while

Loops repeat a block of code while a condition is satisfied or while elements remain in a sequence.

// for loop
for (int i = 1; i <= 5; i++) {
    System.out.println(i);
}

// while loop
int count = 1;
while (count <= 5) {
    count++;
}

// do-while: executes at least once
int value = 1;
do {
    System.out.println(value);
    value++;
} while (value <= 5);

Use enhanced for loops to iterate over arrays and collections when an index is not required.

Topic 12

12. Break and Continue

break terminates the nearest loop or switch statement. continue skips the remaining statements in the current loop iteration and moves to the next iteration.

for (int i = 1; i <= 10; i++) {
    if (i == 3) continue;
    if (i == 8) break;

    System.out.println(i);
}

Java also supports labeled break and continue for nested loops. Use labels sparingly because they can make control flow harder to follow.

Topic 13

13. Arrays – Single and Multidimensional

An array stores a fixed number of elements of the same component type. Array indexing starts at zero.

int[] marks = {80, 90, 75, 88};

for (int mark : marks) {
    System.out.println(mark);
}

// Two-dimensional array
int[][] matrix = {
    {1, 2},
    {3, 4}
};

System.out.println(matrix[1][0]); // 3

Understand array declaration, initialization, length, traversal, copying, sorting and common exceptions such as ArrayIndexOutOfBoundsException.

Arrays have fixed length. Use ArrayList when the collection needs to grow or shrink dynamically.

4. Strings and Object Fundamentals

Topic 14

14. Strings and String Pool

String represents text and is immutable. Java maintains a string pool to reuse certain string instances and reduce unnecessary object creation.

String first = "Java";
String second = "Java";

System.out.println(first == second);       // Usually true
System.out.println(first.equals(second));  // true

The == operator compares references for objects. equals() compares logical content when correctly implemented by the class.

String literals are interned. The intern() method can return the canonical pooled representation of a string.

Topic 15

15. String vs StringBuilder vs StringBuffer

ClassBehaviorTypical use
StringImmutableText values that do not change
StringBuilderMutable, not synchronizedEfficient local string construction
StringBufferMutable, synchronized methodsLegacy synchronized string operations
StringBuilder builder = new StringBuilder();

builder.append("Hello");
builder.append(" ");
builder.append("Java");

String result = builder.toString();

Repeated String concatenation in loops can create many temporary objects. StringBuilder is usually preferred for repeated modifications within one thread.

Topic 16

16. Immutable Objects

An immutable object cannot change its observable state after construction.

Typical design practices include:

  • Make the class final when inheritance must not alter immutability.
  • Keep fields private and final.
  • Initialize fields through constructors.
  • Do not provide setters.
  • Use defensive copies for mutable inputs and outputs.
public final class Money {
    private final BigDecimal amount;

    public Money(BigDecimal amount) {
        this.amount = Objects.requireNonNull(amount);
    }

    public BigDecimal getAmount() {
        return amount;
    }
}

Immutable objects are easier to reason about and are useful in concurrent applications, caching and value-based domain models.

Topic 17

17. Wrapper Classes

Wrapper classes represent primitive values as objects.

PrimitiveWrapper
intInteger
longLong
doubleDouble
floatFloat
charCharacter
booleanBoolean
byteByte
shortShort

Wrapper classes are required when working with generic collections such as List<Integer>, because Java generics use reference types rather than primitive types.

Topic 18

18. Autoboxing and Unboxing

Autoboxing automatically converts a primitive value into its corresponding wrapper object. Unboxing converts a wrapper object back into a primitive value.

Integer number = 100; // Autoboxing
int value = number;   // Unboxing

List values = new ArrayList<>();
values.add(10);

Be careful when unboxing null wrapper references: it causes NullPointerException. Also understand wrapper caching and why object identity should not be used for numeric value comparison.

5. Methods, Constructors and Keywords

Topic 19

19. Methods and Method Overloading

A method defines a reusable operation. It may accept parameters and return a value.

public int add(int a, int b) {
    return a + b;
}

public double add(double a, double b) {
    return a + b;
}

Method overloading means defining multiple methods with the same name but different parameter lists. Return type alone cannot distinguish overloaded methods.

Topic 20

20. Constructors

A constructor initializes a newly created object. Its name matches the class name and it has no return type.

public class Employee {
    private String name;

    public Employee(String name) {
        this.name = name;
    }
}

If no constructor is declared, the compiler may provide a default no-argument constructor. Once you declare a constructor, that implicit constructor is not generated.

Topic 21

21. Constructor Overloading

Constructor overloading allows objects to be initialized in different ways.

public class Employee {
    private String name;
    private int age;

    public Employee(String name) {
        this(name, 0);
    }

    public Employee(String name, int age) {
        this.name = name;
        this.age = age;
    }
}

Constructor chaining using this() avoids duplicating initialization logic. A this() call must be the first statement in a constructor.

Topic 22

22. Static Variables, Methods and Blocks

Static members belong to the class rather than individual object instances.

public class Employee {
    static String company = "RBUtech";
    static int count = 0;

    static {
        System.out.println("Class initialized");
    }

    public Employee() {
        count++;
    }

    static int getCount() {
        return count;
    }
}

Static methods cannot directly access instance members without an object reference. Static initialization occurs as part of class initialization.

Topic 23

23. Instance Variables and Methods

Instance variables belong to individual objects. Each object has its own instance state. Instance methods operate on the current object's state.

class Account {
    private double balance;

    public void deposit(double amount) {
        if (amount <= 0) {
            throw new IllegalArgumentException();
        }
        balance += amount;
    }

    public double getBalance() {
        return balance;
    }
}

Instance members are central to object-oriented modeling. Protect state and expose meaningful operations rather than allowing uncontrolled changes.

Topic 24

24. This and Super Keywords

this refers to the current object. It can access current instance members and invoke another constructor in the same class.

super refers to the superclass portion of the current object. It can invoke superclass constructors and access accessible superclass members.

class Person {
    String name;

    Person(String name) {
        this.name = name;
    }
}

class Employee extends Person {
    int id;

    Employee(String name, int id) {
        super(name);
        this.id = id;
    }
}
Topic 25

25. Final Keyword

The final keyword restricts reassignment or overriding depending on where it is used.

  • Final variable: can be assigned once.
  • Final method: cannot be overridden in a subclass.
  • Final class: cannot be subclassed.
final int MAX_RETRIES = 3;

final class SecurityPolicy {
    // This class cannot be extended.
}

A final reference cannot point to another object, but the referenced object's internal state may still be mutable.

Topic 26

26. Access Modifiers

Access modifiers control where classes, constructors, methods and fields can be accessed.

ModifierAccessibility
publicAccessible from anywhere, subject to module/package visibility rules
protectedSame package and qualifying subclass access
default (package-private)Same package
privateDeclaring class

Use the least permissive access level that satisfies the design. This helps maintain encapsulation and reduces accidental dependencies.

Topic 27

27. Packages and Imports

Packages organize related classes and help avoid naming conflicts. An import statement allows source code to refer to types by their simple names.

package com.rbutech.employee;

import java.util.List;
import java.util.ArrayList;

public class EmployeeService {
    private final List employees = new ArrayList<>();
}

Understand package naming conventions, static imports, fully qualified names and the difference between package organization and the Java module system.

6. Object-Oriented Programming

Topic 28

28. Object-Oriented Programming (OOP)

Object-oriented programming models software using objects that combine state and behavior.

The four commonly taught OOP pillars are encapsulation, inheritance, polymorphism and abstraction.

OOP helps developers organize complex systems into understandable components. In enterprise systems, domain concepts such as Customer, Account, Order and Payment can be represented using suitable classes and interfaces.

Good object-oriented design is about assigning responsibilities clearly, not creating a class for every small operation.
Topic 29

29. Encapsulation

Encapsulation combines data and operations inside a class while controlling access to internal state.

class BankAccount {
    private BigDecimal balance = BigDecimal.ZERO;

    public void deposit(BigDecimal amount) {
        if (amount.signum() <= 0) {
            throw new IllegalArgumentException("Invalid amount");
        }
        balance = balance.add(amount);
    }

    public BigDecimal getBalance() {
        return balance;
    }
}

The balance cannot be changed directly from outside the class. Changes must follow the class's validation rules.

Topic 30

30. Inheritance

Inheritance allows a class to extend another class and reuse or specialize its behavior.

class Vehicle {
    void start() {
        System.out.println("Vehicle started");
    }
}

class Car extends Vehicle {
    void openBoot() {
        System.out.println("Boot opened");
    }
}

Java supports single class inheritance: a class can extend only one direct superclass. It can implement multiple interfaces.

Prefer composition over inheritance when the relationship is not a genuine "is-a" relationship.
Topic 31

31. Polymorphism

Polymorphism allows a common reference type to represent different concrete implementations.

Runtime polymorphism is commonly achieved through method overriding and dynamic method dispatch.

interface Payment {
    void pay(BigDecimal amount);
}

class CardPayment implements Payment {
    public void pay(BigDecimal amount) {
        System.out.println("Card payment");
    }
}

class UpiPayment implements Payment {
    public void pay(BigDecimal amount) {
        System.out.println("UPI payment");
    }
}

Payment payment = new CardPayment();
payment.pay(new BigDecimal("100.00"));

The implementation selected at runtime depends on the actual object, not merely the reference type.

Topic 32

32. Abstraction

Abstraction exposes essential operations while hiding implementation details.

Interfaces and abstract classes are the primary language constructs used to model abstraction.

For example, a payment service can expose a pay operation without requiring its caller to understand the internal steps of a card, bank or wallet integration.

Topic 33

33. Abstract Classes

An abstract class cannot be instantiated directly. It can contain abstract methods, concrete methods, fields and constructors.

abstract class Report {
    abstract void generate();

    void printHeader() {
        System.out.println("Company Report");
    }
}

class SalesReport extends Report {
    @Override
    void generate() {
        System.out.println("Generating sales report");
    }
}

Use an abstract class when related subclasses share state or common implementation in addition to requiring specialized behavior.

Topic 34

34. Interfaces

An interface defines a contract that implementing classes agree to fulfill.

interface Notification {
    void send(String message);
}

class EmailNotification implements Notification {
    public void send(String message) {
        System.out.println("Email: " + message);
    }
}

Interfaces support loose coupling and allow multiple implementations. A class can implement more than one interface.

Topic 35

35. Default and Static Interface Methods

Default methods provide an implementation inside an interface. Static methods belong to the interface itself and are called using the interface name.

interface Logger {
    default void info(String message) {
        System.out.println("INFO: " + message);
    }

    static Logger console() {
        return new Logger() {};
    }
}

Default methods help evolve interfaces while retaining compatibility for existing implementations. Be aware of conflicts when inherited defaults have the same signature.

Topic 36

36. Functional Interfaces

A functional interface has exactly one abstract method. It can be implemented using a lambda expression or method reference.

@FunctionalInterface
interface Calculator {
    int calculate(int a, int b);
}

Calculator addition = (a, b) -> a + b;

System.out.println(addition.calculate(10, 20));

Common built-in functional interfaces include Predicate, Function, Consumer and Supplier. They are widely used in the Stream API.

7. Advanced Class Concepts

Topic 37

37. Nested and Inner Classes

A nested class is declared inside another class. A non-static nested class is commonly called an inner class and has access to the enclosing object's instance members.

Types include static nested classes, member inner classes, local classes and anonymous classes.

class Outer {
    private String message = "Hello";

    class Inner {
        void display() {
            System.out.println(message);
        }
    }
}
Topic 38

38. Anonymous Classes

An anonymous class is a class expression without a declared name. It can extend a class or implement an interface for a one-off implementation.

Runnable task = new Runnable() {
    @Override
    public void run() {
        System.out.println("Task running");
    }
};

new Thread(task).start();

For functional interfaces, lambda expressions are generally more concise. Anonymous classes remain useful when multiple methods or additional local behavior are required.

Topic 39

39. Enum

An enum defines a fixed set of named constants. Enums are type-safe and can contain fields, constructors and methods.

enum OrderStatus {
    NEW,
    PROCESSING,
    SHIPPED,
    DELIVERED,
    CANCELLED
}

OrderStatus status = OrderStatus.SHIPPED;

Use enums instead of arbitrary strings when a value must belong to a known, finite set.

Topic 40

40. Object Class Methods

Object is the root class of the Java class hierarchy for reference types. Important methods include:

  • toString() — textual representation.
  • equals() — logical equality.
  • hashCode() — hash value used by hash-based structures.
  • getClass() — runtime class information.
  • clone() — protected cloning mechanism with special considerations.
  • wait(), notify(), notifyAll() — intrinsic monitor coordination.
  • finalize() — deprecated and subject to removal; do not use for resource management.

Override methods carefully and follow their documented contracts.

Topic 41

41. equals() and hashCode()

equals() defines logical equality. hashCode() provides a hash value used by hash-based collections.

The contract requires that equal objects have equal hash codes. Unequal objects may still have the same hash code.

class Employee {
    private final long id;

    Employee(long id) {
        this.id = id;
    }

    @Override
    public boolean equals(Object obj) {
        if (this == obj) return true;
        if (!(obj instanceof Employee other)) return false;
        return id == other.id;
    }

    @Override
    public int hashCode() {
        return Long.hashCode(id);
    }
}
Incorrect equals() and hashCode() implementations can cause unexpected behavior in HashMap and HashSet.
Topic 42

42. clone() and finalize() Concepts

Object.clone() is a legacy mechanism for copying objects. It requires Cloneable support and normally performs a shallow field copy unless additional logic is implemented.

Shallow copying duplicates references to nested objects; deep copying creates independent copies of mutable nested state.

finalize() was intended to run before object reclamation, but its timing was never reliable. It is deprecated for removal and should not be used for resource cleanup.

Prefer copy constructors, factory methods or explicit copy methods. Use try-with-resources and AutoCloseable for resource management.

8. Exception Handling

Topic 43

43. Exception Handling

Exception handling allows an application to respond to abnormal conditions without losing control of the entire program unexpectedly.

Java uses Throwable as the root of the exception and error hierarchy. Exceptions are conditions applications may handle; Errors generally represent serious problems that applications should not normally attempt to recover from.

Topic 44

44. Checked and Unchecked Exceptions

Checked exceptions are checked by the compiler and must be caught or declared, subject to the language rules.

Unchecked exceptions are RuntimeException subclasses and are not subject to the same catch-or-declare requirement.

// Checked exception example
try {
    Files.readString(Path.of("data.txt"));
} catch (IOException ex) {
    System.err.println("Unable to read file");
}

// Unchecked exception example
int result = 10 / 0; // ArithmeticException
Topic 45

45. Try, Catch and Finally

try contains code that may throw an exception. catch handles matching exceptions. finally normally executes during completion of the try statement, whether or not an exception occurred.

try {
    int result = 10 / 2;
    System.out.println(result);
} catch (ArithmeticException ex) {
    System.out.println("Invalid calculation");
} finally {
    System.out.println("Operation completed");
}

Do not return from finally or use it to hide exceptions. Prefer try-with-resources for closing resources.

Topic 46

46. Throw and Throws

throw explicitly throws an exception object. throws declares exceptions that a method may propagate to its caller.

public void validateAge(int age)
        throws InvalidAgeException {

    if (age < 18) {
        throw new InvalidAgeException("Age must be 18+");
    }
}
Topic 47

47. Custom Exceptions

Custom exceptions represent application-specific failure conditions and make business errors easier to identify.

public class EmployeeNotFoundException
        extends RuntimeException {

    public EmployeeNotFoundException(long id) {
        super("Employee not found: " + id);
    }
}

Use meaningful exception names and preserve the original cause when wrapping another exception. Avoid creating excessive custom exception types without a clear benefit.

Topic 48

48. Try-with-Resources

Try-with-resources automatically closes resources that implement AutoCloseable.

try (BufferedReader reader =
         Files.newBufferedReader(Path.of("input.txt"))) {

    String line;
    while ((line = reader.readLine()) != null) {
        System.out.println(line);
    }
} catch (IOException ex) {
    ex.printStackTrace();
}

It is preferred for streams, readers, writers, JDBC resources and other closeable objects.

Topic 49

49. Exception Propagation

When a method does not handle an exception, it may propagate to its caller. The exception continues up the call stack until a matching handler is found or the thread terminates.

In layered applications, decide which layer can meaningfully handle the exception. Translate low-level failures into meaningful application errors while retaining the original cause.

Topic 50

50. Assertions

Assertions help developers check assumptions during development and testing.

int quantity = 10;
assert quantity > 0 : "Quantity must be positive";

Assertions are disabled by default unless enabled at runtime using -ea. Do not use assertions for validating external user input or enforcing business rules that must always execute.

9. Java I/O, Files and NIO

Topic 51

51. Java I/O Streams

Java I/O provides APIs to read and write data from sources such as files, memory, network connections and other streams.

Important base abstractions include InputStream, OutputStream, Reader and Writer.

Choose the appropriate stream type based on whether the data is binary or character-oriented.

Topic 52

52. Byte Streams and Character Streams

Byte streams process raw bytes. Character streams process text using character encoding.

// Byte-oriented file copy
try (InputStream in = Files.newInputStream(Path.of("a.bin"));
     OutputStream out = Files.newOutputStream(Path.of("b.bin"))) {
    in.transferTo(out);
}

// Character-oriented text reading
try (BufferedReader reader =
         Files.newBufferedReader(Path.of("notes.txt"))) {
    System.out.println(reader.readLine());
}

Always be deliberate about text encoding, especially when handling multilingual data.

Topic 53

53. File Handling

File handling includes creating, reading, writing, copying, moving and deleting files and directories.

Path file = Path.of("employee.txt");

Files.writeString(file, "Employee information");
String content = Files.readString(file);

System.out.println(content);

Use validation and suitable permissions. Never trust a user-supplied path without checking for path traversal and unauthorized access.

Topic 54

54. Serialization and Deserialization

Serialization converts an object into a representation that can be stored or transmitted. Java's built-in object serialization uses Serializable and ObjectOutputStream/ObjectInputStream.

class Employee implements Serializable {
    private static final long serialVersionUID = 1L;
    private String name;
}

Deserialization reconstructs an object from a serialized representation.

Java native deserialization can be dangerous with untrusted data. Prefer safer, explicit data formats such as JSON or Protocol Buffers for many service integrations.
Topic 55

55. Transient Keyword

The transient modifier excludes an instance field from default Java serialization.

class UserSession implements Serializable {
    private String username;
    private transient String temporaryToken;
}

Use it for fields that should not be part of the serialized object representation. It is not a substitute for secure secret management.

Topic 56

56. Externalization

Externalizable provides explicit control over writing and reading an object's serialized representation through writeExternal() and readExternal().

Implementations must provide a public no-argument constructor. The developer is responsible for writing and restoring the required state.

It is a specialized, legacy serialization mechanism; consider whether a modern explicit serialization format is more appropriate.

Topic 57

57. Java NIO

Java NIO introduced buffer-oriented I/O, channels and selectors. It supports scalable I/O designs and is especially relevant to network programming.

Important concepts include:

  • Buffers — containers for data.
  • Channels — connections to entities capable of I/O.
  • Selectors — monitor multiple selectable channels.
  • Non-blocking I/O — operations can return without waiting for all work to complete.
Topic 58

58. NIO.2 and Path API

NIO.2 introduced improved file-system APIs. Path represents a file-system path, while Files provides operations on files and directories.

Path source = Path.of("source.txt");
Path target = Path.of("backup.txt");

Files.copy(source, target,
    StandardCopyOption.REPLACE_EXISTING);

boolean exists = Files.exists(target);

Understand directory traversal, file attributes, symbolic links and file-system providers.

Topic 59

59. File Channels and Buffers

FileChannel supports operations such as reading, writing, positioning, transferring and mapping file data.

try (FileChannel channel =
         FileChannel.open(Path.of("data.txt"),
             StandardOpenOption.READ)) {

    ByteBuffer buffer = ByteBuffer.allocate(1024);

    while (channel.read(buffer) > 0) {
        buffer.flip();
        // Process buffer contents
        buffer.clear();
    }
}

Understand buffer position, limit, capacity, flip(), clear() and compact().

10. Additional Java Fundamentals

Topic 60

60. Regular Expressions

Regular expressions describe patterns used to search, validate and extract text.

String email = "user@example.com";

boolean valid = email.matches(
    "^[A-Za-z0-9+_.-]+@[A-Za-z0-9.-]+$"
);

System.out.println(valid);

Java provides Pattern and Matcher for reusable patterns and advanced matching. Avoid overly complex expressions that are difficult to maintain or vulnerable to catastrophic backtracking.

Topic 61

61. Date and Time API (Java 8+)

The java.time API provides immutable classes for date, time, duration, period, time zones and formatting.

ClassPurpose
LocalDateDate without time or zone
LocalTimeTime without date or zone
LocalDateTimeDate and time without zone
InstantPoint on the UTC timeline
ZonedDateTimeDate and time with time zone
DurationTime-based amount
PeriodDate-based amount
LocalDate today = LocalDate.now();
LocalDate nextWeek = today.plusDays(7);

ZonedDateTime dubaiTime =
    ZonedDateTime.now(ZoneId.of("Asia/Dubai"));

For applications used across countries, understand UTC storage, time-zone conversion and daylight-saving rules.

Topic 62

62. Locale and Internationalization

Internationalization (i18n) prepares applications to support different languages, countries and regional formats.

Locale represents language and regional preferences. ResourceBundle supports localized messages. NumberFormat and DateTimeFormatter support locale-sensitive formatting.

Locale locale = Locale.forLanguageTag("en-IN");

NumberFormat formatter =
    NumberFormat.getCurrencyInstance(locale);

System.out.println(formatter.format(15000));
Topic 63

63. Annotations

Annotations provide metadata about program elements. They are used by compilers, frameworks, build tools and runtime libraries.

Common built-in annotations include:

  • @Override
  • @Deprecated
  • @SuppressWarnings
  • @FunctionalInterface
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
@interface Auditable {
    String action();
}

class AccountService {
    @Auditable(action = "ACCOUNT_UPDATE")
    public void updateAccount() {
        // Business logic
    }
}
Topic 64

64. Reflection API

Reflection allows a program to inspect classes, constructors, methods, fields and annotations at runtime.

Class type = String.class;

System.out.println(type.getName());

for (Method method : type.getDeclaredMethods()) {
    System.out.println(method.getName());
}

Frameworks use reflection for dependency injection, object mapping, testing and annotation processing at runtime.

Reflection can reduce compile-time safety and may be restricted by module boundaries. Use it only when dynamic inspection or invocation is genuinely required.
Topic 65

65. ClassLoader Architecture

Class loaders load class definitions into the JVM. The built-in hierarchy commonly includes:

  • Bootstrap ClassLoader
  • Platform ClassLoader
  • Application ClassLoader

Java commonly uses parent delegation: a class loader delegates loading to its parent before attempting to load a class itself. Custom class loaders can support specialized application loading requirements.

Class loading, linking and initialization are distinct stages in the JVM lifecycle.

11. JVM Internals and Memory Management

Topic 66

66. Garbage Collection Fundamentals

Garbage collection automatically reclaims heap memory occupied by objects that are no longer reachable through live references from GC roots.

Developers should understand object reachability, allocation pressure, garbage collection pauses and the difference between memory reclamation and resource cleanup.

Garbage collection does not automatically close files, database connections or sockets. Use explicit resource management for those resources.

Topic 67

67. Java Memory Model

The Java Memory Model defines how threads interact through memory and which visibility and ordering guarantees are provided.

It is essential for understanding data races, synchronization, volatile fields, final-field semantics and happens-before relationships.

A program can appear correct in single-threaded testing and still fail under concurrency because of visibility or ordering problems.
Topic 68

68. JVM Internals

The JVM includes several major runtime components:

  • Class Loader Subsystem
  • Runtime Data Areas
  • Execution Engine
  • Interpreter
  • JIT Compiler
  • Garbage Collector
  • Native Method Interface

Understand how bytecode is loaded, verified, prepared, initialized and executed. This knowledge helps investigate class-loading errors, memory problems and runtime performance issues.

Topic 69

69. Heap and Stack Memory

Heap: Runtime memory area where objects and arrays are generally allocated. It is managed by the garbage collector.

Java stacks: Each thread has its own JVM stack containing frames for method invocations. Frames hold local variables, intermediate results and method execution state.

public void process() {
    int count = 10;                 // Local variable
    Employee employee = new Employee(); // Object on heap
}

The local reference is stored in the method frame, while the referenced object is generally allocated on the heap. JVM optimizations can make physical allocation more complex.

Topic 70

70. Metaspace

Metaspace stores class metadata in native memory. It replaced the permanent generation in HotSpot beginning with Java 8.

Metaspace usage can grow when applications load many classes or repeatedly create class loaders that cannot be reclaimed.

Useful diagnostic topics include class-loader leaks, class unloading and Metaspace-related OutOfMemoryError conditions.

Topic 71

71. Garbage Collection Algorithms

Garbage collectors use different strategies to identify and reclaim unreachable objects.

Important concepts include:

  • Mark and Sweep
  • Mark and Compact
  • Copying collection
  • Generational collection
  • Concurrent collection
  • Region-based heap management

Common HotSpot collectors include Serial, Parallel, G1, ZGC and Shenandoah, with availability and support depending on the JDK distribution and release.

Learn how to select a collector based on throughput, latency, heap size and operational requirements.

Topic 72

72. JVM Tuning and Memory Management

JVM tuning involves measuring and adjusting runtime behavior to meet application performance and reliability goals.

Important areas include:

  • Heap sizing using -Xms and -Xmx.
  • Garbage collector selection.
  • GC log analysis.
  • Thread and stack investigation.
  • Metaspace monitoring.
  • Heap dumps and memory leak analysis.
  • CPU profiling and allocation profiling.
# Example JVM options
java -Xms512m -Xmx2g \
     -Xlog:gc* \
     -jar application.jar

Use tools such as jcmd, jstack, jmap, Java Flight Recorder and Java Mission Control where appropriate. Tool availability and options depend on the JDK version.

Senior developer principle: Never tune JVM parameters based only on assumptions. Capture metrics, reproduce the workload, identify the bottleneck and validate the improvement.

12. Complete Core Java Practical Project

Employee Management Console Application

Build a small application that combines the important concepts covered in this chapter.

Requirements:

  • Create an Employee class with private fields.
  • Use constructors to initialize employee details.
  • Use encapsulation and validation.
  • Store employees in an ArrayList.
  • Implement add, search, update and delete operations.
  • Use interfaces for service contracts.
  • Handle invalid input using custom exceptions.
  • Save and read employee data from a file.
  • Use LocalDate for joining dates.
  • Write unit tests for important business operations.
public class Employee {
    private final long id;
    private String name;
    private BigDecimal salary;

    public Employee(long id, String name, BigDecimal salary) {
        if (id <= 0) {
            throw new IllegalArgumentException("Invalid ID");
        }
        this.id = id;
        this.name = Objects.requireNonNull(name);
        this.salary = Objects.requireNonNull(salary);
    }

    public long getId() {
        return id;
    }

    public String getName() {
        return name;
    }

    public BigDecimal getSalary() {
        return salary;
    }

    public void updateSalary(BigDecimal salary) {
        if (salary.signum() < 0) {
            throw new IllegalArgumentException("Invalid salary");
        }
        this.salary = salary;
    }
}

Expected result: A maintainable console-based application that demonstrates object-oriented design, collections, validation, exception handling and file operations.
